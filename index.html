            How to use GitHub access
            
                
            GitHub access lets Codex and Claude Code fetch one GitHub repository from the guest. Brig keeps the token on this Mac and adds it to each request. The guest never receives the token.
            
                
            When to use it
            
                
              
                  
            • The project repository is private, and an agent must run git fetch or git pull to get new commits.
              • 
                  
            • An agent must compare the work with a remote branch, for example git diff origin/main after a fetch.
              • 
                  
            • An agent must clone the same repository again in the guest, for example in a temporary folder for a test.
              • 
                
            
                
            How to use it
            
                
              
                  
            1. On GitHub, create a fine-grained personal access token. Select only this repository. Give it Contents: Read-only permission. Select an expiry date that suits the project.
              2. 
                  
            2. In GitHub repository, enter owner/repository, for example octo-org/web-app. In GitHub access token, paste the token.
              3. 
                  
            3. Select Save fetch access. If the environment is running, the button is Stop environment and save access. It ends the chats and guest terminals of this project. Saved chats stay available.
              4. 
                  
            4. If macOS asks for Keychain access, allow it. Then select Check access.
              5. 
                  
            5. Start a chat. Agents can use the normal GitHub addresses. Brig sends https://github.com/… and git@github.com:… addresses through the access route.
              6. 
                
            
                
            Limits
            
                
              
                  
            • Only fetch and clone work. git push, the GitHub API, the gh command, issues and pull requests do not work through this access.
              • 
                  
            • Only the saved repository works. A fetch from a different repository is refused. To change the repository, select Revoke access and save the new repository.
              • 
                  
            • The network mode must be Access allowed by policy, and the project policy must be attached. Offline mode does not support GitHub access.
              • 
                  
            • The GitHub access policy denies all other destinations. You cannot use it together with Enable all public internet access in Network.
              • 
                  
            • Tugboat checks the local grant only. GitHub decides if the token can read the repository, so the status shows GitHub fetch permission as unverified.
              • 
                
            
                
            If it does not work
            
                
              
                  
            • GitHub refuses the fetch: check that the token is not expired, that it includes this repository, and that it has Contents read permission. Then select Replace token.
              • 
                  
            • Brig cannot verify the saved grant: replace the token, or revoke access and save it again.
              • 
                  
            • Attach the project policy and use Isolated mode before saving GitHub access: in General, set Network to Access allowed by policy. In Network, open Policy document and binding and attach the policy.
              • 
                  
            • A save or revoke stopped before it completed: select Check access, then retry the same action.
              •

            How to use the preview
            
                
            The preview connects a port on this Mac to a port in the project guest. Your Mac browser and tools can then reach a server that runs in the guest.
            
                
            When to use it
            
                
              
                  
            • Look at a web app that an agent started in the guest, for example a Vite, Next.js, Rails, Django or Laravel development server.
              • 
                  
            • Check a user interface change in your Mac browser while the chat continues.
              • 
                  
            • Send requests to an HTTP API in the guest from a Mac tool, for example curl or an API client.
              • 
                
            
                
            How to use it
            
                
              
                  
            1. Prepare the project environment. The Overview section shows its state.
              2. 
                  
            2. Start the server in the guest. Ask the agent, or open Environment → Guest terminal. Example: npm run dev -- --host 0.0.0.0 --port 5173.
              3. 
                  
            3. In Guest port, enter the port of the server, for example 5173. In Mac port, enter a free port on this Mac, for example 5173 or 8080.
              4. 
                  
            4. Select Publish preview. Then select Check preview. When the server is ready, select Open in browser. The address is http://127.0.0.1:<Mac port>.
              5. 
                  
            5. When you do not need the preview, select Close preview.
              6. 
                
            
                
            Limits
            
                
              
                  
            • Only this Mac can open the preview. Other devices on your network cannot reach it.
              • 
                  
            • Each project publishes one port. Close the preview before you select different ports. A Mac port can serve only one project.
              • 
                  
            • Check preview expects a plain HTTP response. A server that answers only HTTPS shows as not responding.
              • 
                  
            • The preview does not change the network policy. It does not give the guest access to services on this Mac.
              • 
                  
            • When the environment stops, Tugboat keeps the approved port. Brig opens it again when the environment starts.
              • 
                
            
                
            If it does not work
            
                
              
                  
            • The guest web server has not responded: make sure that the server runs and uses the guest port. If it still does not respond, start it on all guest addresses (0.0.0.0), not only on localhost.
              • 
                  
            • The host port is already in use: close the Mac program that uses the port, or select a different Mac port.
              • 
                  
            • Prepare the project environment before publishing a preview: open Overview and select Prepare environment.
              •
