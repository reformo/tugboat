Legacy stock image fixture

This infrastructure fixture uses an immutable Linux ARM64 Claude Code stock image from Brig's signed public registry. Tugboat's require setting and Brig's default signer check cover the image and the boot assets. The runner also tries a public Ubuntu image against the same policy and checks for a signature refusal.

The Codex release workflow signs the pinned Linux ARM64 package, which includes the resources used by its workspace sandbox. The runner checks the archive and bundle hashes and verifies the signature for the exact OpenAI release tag. It stages the package in the guest home and compares the executable hash on both sides of the mount. The guest policy allows provider endpoints only, so the guest does not obtain programs from a package server during preparation.

Application setup

New registrations pin an agent-free Renovate base image by digest. Brig requires the Renovate promotion workflow signature and checks the boot assets under their own publisher policy. Existing registrations keep their saved image digest and approved profile. Both paths use the same named guest home and project policy.

When the guest is ready, the Mac starts one worker per agent. Each worker selects the vendor’s stable release and checks its signed package. It stages verified files in a new directory under the running guest’s persistent home. It checks the installed version and the selected new-chat and resume options inside that guest. It then replaces the agent’s active link atomically.

The terminal can open during these checks. The first successful check enables the corresponding agent. The Mac stores verified packages across projects. A failed update uses the previous verified installation if its compatibility checks pass. The updater leaves saved transcripts and usage records in place.

One guest and two launch targets

The proof profile uses Bash as the neutral profile executable. Brig accepts a session policy on an agent profile. Each proof launch names the agent executable and passes that agent's normal arguments to the same Brig session. The project mounts at /work/sample project. The guest home mounts at /root.

Codex uses /root/.codex for its settings and saved sessions. Claude uses the memory filesystem at /brig/claude for its access copy. The profile binds Claude's persistent configuration and history paths under /root/.claude into that filesystem. Stopping the guest clears its memory filesystem. The two guest processes can access the same project and share the guest permissions.

With --keep, run the native terminal check with the temporary directory printed by the first check. It uses the same pseudo-terminal code as the desktop app. The test verifies input reaches two independent terminals in the same guest.

Live chat checks require permission to use the selected Tugboat Dev provider connections. Start with current access in the Dev records and the same verified disposable guest.
